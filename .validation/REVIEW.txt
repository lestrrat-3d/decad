FIXES FOR REVIEW FINDINGS
1. require_memory rejects final memory.peak >= 3 GiB even when the live sampler missed it.
2. SIGTERM/SIGINT install the vetted request_cancel handler. Bounded commands observe it,
   and all workload failure paths reach exact removal with its independent reserved budget.
3. Removal is unconditional in a nested finally. Inspect and counter failures cannot gate it.
4. The unique container name is saved in per-stage and overall reports before docker create.
   An uncertain/timed-out create is removed using that exact persisted name.
5. Final capture uses the vetted bounded helper with a 1.5-second deadline. Failure paths in
   bounded_process pause/capture within 1.5 seconds, then reserve 3.5 seconds for removal,
   launcher cleanup and verification. The initial inspect timeout is 2 seconds, not 30.
6. /control and /src are read-only mounts outside the writable scratch filesystem.
   /out alone exposes an owned, fixed-size 8 GiB ext4 scratch filesystem. stage.sh keeps
   the vetted 1 GiB per-file ulimit. Go caches, module caches, linker temps and tool
   extraction share that filesystem. Container /tmp is a separate 64 MiB tmpfs charged
   to the same memory cgroup. Source archives have a 128 MiB hard output cap; reports
   have a 64 KiB cap, and cumulative workload text has an 8 MiB cap.
7. Launcher wait/cleanup exceptions are caught by the vetted bounded_process and run_stage.
   Per-stage and overall evidence writing is the innermost finally. Removal, capture,
   memory validation and disk-cleanup errors cannot skip that final write attempt.
8. Only exact owned container IDs/names, process groups launched by this controller and
   the run's unique scratch image are cleaned. No unrelated worktrees or caches are touched.
9. A failed removal/verification is an inconclusive failure. Report errors rather than
   claiming cleanup succeeded. An inability to write artifacts cannot be called success.
10. No Python container worker is used. Python runs on the GitHub-hosted machine; it uses
    the vetted docker-exec Bash lifecycle in the official Go container.
